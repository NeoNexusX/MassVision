# 技术栈

本页面向贡献者，梳理 SpatialXomics 前端项目实际使用的技术栈、目录结构与开发脚本。整体业务架构边界见 [前端架构边界](./前端架构边界)。

## 一、环境要求

- Node.js `^20.19.0` 或 `>=22.12.0`
- 包管理器：npm（仓库提交了 `package-lock.json`）

```bash
npm install
npm run dev   # 同时启动 SPA(5173) 与文档站(5174)
```

## 二、核心依赖

| 分类 | 依赖 | 作用 |
|---|---|---|
| 核心框架 | Vue 3 + TypeScript | 组合式 API、SFC、静态类型 |
| 构建工具 | Vite 7 + `@tailwindcss/vite` | 开发服务器、生产构建 |
| 状态管理 | Pinia | feature 内的全局/跨组件状态（如 `authStore`） |
| 路由 | Vue Router | History 模式 + 路由守卫 |
| UI | Tailwind CSS v4 + DaisyUI v5 + Iconify（离线打包，见 [图标使用规范](./图标使用规范)） | 原子化样式与组件库 |
| 图表 | ECharts、vue3-calendar-heatmap | 统计图表、提交热力图 |
| MSI 数据 | zarrita（Zarr 读取）、@zip.js/zip.js（上传打包）、zstddec（zstd 解压）、hash-wasm（文件哈希） | 解析与校验 imzML 衍生的成像数据 |
| 对象存储 | ali-oss | 阿里云 OSS 分片上传 / 下载预签名 URL |
| 网络请求 | Axios + qs | HTTP 客户端与查询参数序列化 |
| 加密 | crypto-js | 前端侧加密（如密码传输前处理） |
| 地区数据 | i18n-iso-countries | 用户资料中的国家/地区选项 |
| 文档站 | VitePress | `docs/` 下的中英文文档（与 SPA 同仓库，见 [文档维护](./文档维护)） |
| 测试 | Vitest（单测）+ Playwright（E2E） | |
| 代码规范 | ESLint 9（flat config）+ Prettier | |

完整版本号见根目录 `package.json`。

## 三、项目结构

```
src/
├── app/components/        # 应用级外壳组件（Navbar、NavDrawer、NavFab）
├── assets/                # Tailwind/DaisyUI 主题样式
├── features/              # 按业务领域划分的功能模块
│   ├── assistant/         # 悬浮 AI 助手
│   ├── auth/              # 登录/注册/找回密码、authStore
│   ├── datasets/          # 数据集浏览、筛选、下载
│   ├── home/              # 首页（统计数据、热力图）
│   ├── upload/            # imzML 上传（压缩/哈希/OSS 分片/续传）
│   ├── users/              # 用户管理（管理员面板）
│   └── workspace/         # 分析工作区
│       ├── analysis/      # 分析构建器（数据源、预处理管线）
│       ├── dashboard/      # 任务/结果/活动看板
│       └── results/       # 结果可视化（离子图/谱图/ROI/UMAP-KMeans）
├── router/                 # 路由声明与守卫
├── services/                # 跨 feature 服务（OSS 客户端、远程 Zarr 访问）
├── shared/                  # 不依赖任何 feature 的复用层（api/components/composables/utils/types）
├── views/                   # 路由页面，组装 feature 能力
├── workers/                  # Web Worker（imzML 压缩等耗时任务）
└── main.ts / App.vue
```

每个 `features/<module>` 内部按 `api`、`components`、`composables`、`services`、`stores`、`types`、`utils` 继续拆分；具体依赖方向与边界约束见 [前端架构边界](./前端架构边界)。

## 四、常用脚本（见 package.json）

| 命令 | 作用 |
|---|---|
| `npm run dev` | 并行启动 SPA（`vite`，5173）与文档站（`vitepress dev`，5174） |
| `npm run dev:app` | 只启动 SPA |
| `npm run build` | `type-check` + `vite build`，产物输出到 `dist/` |
| `npm run preview` | 预览生产构建 |
| `npm run type-check` | `vue-tsc --build` |
| `npm run lint` / `lint:check` | ESLint 自动修复 / 仅检查（含目录导入边界规则） |
| `npm run format` / `format:check` | Prettier 格式化 `src/` / 仅检查 |
| `npm run test:unit` | Vitest 单元测试（watch 模式） |
| `npm run test:unit:run` | Vitest 单次运行（CI 用，`--passWithNoTests`） |
| `npm run test:e2e` | Playwright E2E（需先 `build` + `preview`） |
| `npm run check` | 并行执行 `type-check` + `lint:check` + `test:unit:run`，CI 与本地提测前都跑这条 |
| `npm run docs:dev` / `docs:build` / `docs:preview` | 文档站开发/构建/预览，详见 [文档维护](./文档维护) |

## 五、CI/CD 与部署

- **测试**（`.github/workflows/test.yml`）：PR 触发 `npm run check`；另一个 job 跑 `npm run build` + `playwright install` + `npm run test:e2e`，失败时上传 Playwright 报告。
- **部署**（`deploy-dev.yml` / `deploy-main.yml`）：`npm ci` → `npm run check` → 构建 Docker 镜像并推送到镜像仓库 → 通过 SSH 在目标服务器上部署。
- **Docker**：`docker/Dockerfile` 多阶段构建，把 SPA 的 `dist/` 与文档站的 `dist-docs/` 一并拷贝进 nginx 镜像；`docker/nginx.conf.template` 中 `location /docs/` 必须与 VitePress 的 `base: '/docs/'` 保持一致。

## 六、其他约定

- 认证使用后端签发的 JWT，前端不做密码哈希存储，仅在传输前用 `crypto-js` 处理；找回密码走邮箱验证码（见 `src/features/auth/composables/useForgotPassword.ts`）。
- 路由懒加载、`history` 模式 fallback 已在 `vite.config.ts` / `vue-router` 配置中处理，无需手动配置 Nginx `try_files`（已在 `nginx.conf.template` 内置）。
- 新增依赖前先确认 `shared`/`features` 边界（见 [前端架构边界](./前端架构边界)），避免循环依赖或越界引用。

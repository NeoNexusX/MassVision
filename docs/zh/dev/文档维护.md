# 文档维护

本项目文档由 [VitePress](https://vitepress.dev/) 驱动，源文件位于仓库根目录的 `docs/` 下，与前端 SPA 共用同一仓库，最终作为静态文件部署在站点的 `/docs/` 子路径。本页介绍如何写、如何改、如何在本地看效果。

## 一、目录结构

```
docs/
├── .vitepress/
│   ├── config.ts          # 站点配置：导航、侧边栏、i18n、构建参数
│   ├── theme/             # 自定义主题（custom.css 等）
│   └── cache/             # 本地缓存（已 gitignore，无需手动处理）
├── en/                    # 英文文档（默认语言，URL 无 /en 前缀）
│   ├── index.md           # 英文首页
│   ├── guide/             # 用户指南
│   └── dev/               # 开发者文档
└── zh/                    # 中文文档（URL 带 /zh 前缀）
    ├── index.md           # 中文首页
    ├── guide/             # 用户指南
    └── dev/               # 开发者文档（本页所在位置）
```

关键约定：

- **语言在最外层**：`en/` 是默认语言，URL 会被改写去掉 `/en` 前缀；`zh/` 保留 `/zh` 前缀。配置见 `.vitepress/config.ts` 的 `rewrites`。
- **分类在第二层**：目前是 `guide/`（面向用户）与 `dev/`（面向开发者）。新增分类时，中英文目录要同步建立。
- **文件名即 URL**：例如 `docs/zh/dev/文档维护.md` 对应 `/docs/zh/dev/文档维护`。中文文件名是允许的，现有文档（如 `技术栈.md`）已在使用。

## 二、新增或修改文档

### 2.1 修改已有页面

直接编辑对应 `.md` 文件即可，保存后开发服务器会热更新（见第四节）。

### 2.2 新增一篇文档

1. **在中英文目录各放一份**，文件名保持对应关系。例如：
   - `docs/zh/guide/export-data.md`
   - `docs/en/guide/export-data.md`
2. **在 `.vitepress/config.ts` 里注册到侧边栏**，否则页面虽然能通过 URL 访问，但侧边栏看不到入口。
   - 英文：在 `en.sidebar['/guide/']` 的 `items` 里追加一项。
   - 中文：在 `zh.sidebar['/zh/guide/']` 的 `items` 里追加一项。
3. **如果是新分类**（不是 guide/dev），还要在 `nav` 里加一项顶部导航，并新增一组 `sidebar` 键值。

### 2.3 Frontmatter

每篇 `.md` 文件可以在最顶部用 YAML frontmatter 设置页面元信息，最常用的是 `home` 布局（首页）和普通页的 `title` / `outline`：

```markdown
---
title: 文档维护
outline: [2, 3]   # 右侧大纲只展示 h2 ~ h3
---
```

不写 frontmatter 也可以，VitePress 会用第一个 `#` 作为标题。

## 三、写作语法

### 3.1 标准 Markdown

标题、列表、表格、代码块、链接、图片等 CommonMark 语法全部支持。代码块建议显式写语言以启用语法高亮：

````markdown
```ts
const x: number = 1
```
````

### 3.2 VitePress 提示容器

四种常用提示框，渲染为带颜色的卡片：

```markdown
::: tip 小贴士
辅助性的补充信息。
:::

::: warning 注意
易踩坑的细节。
:::

::: danger 警告
会破坏数据 / 不可逆的操作。
:::

::: details 点击展开
默认折叠的长内容（适合放完整命令输出、长配置）。
:::
```

### 3.3 数学公式

`.vitepress/config.ts` 已启用 `markdown.math`，行内用 `$...$`，块级用 `$$...$$`：

```markdown
行内：$E = mc^2$

块级：
$$
\hat{y} = \mathrm{softmax}(Wx + b)
$$
```

### 3.4 站内链接

- **相对路径**（推荐）：`[查看数据](./view-data)` —— 跟着文件搬家不会断。
- **绝对路径**：`[查看数据](/zh/guide/view-data)` —— 注意中文站点需要带 `/zh` 前缀。
- **跨语言链接**：右上角的语言切换器会自动处理，无需手写。

::: warning 死链会让构建失败
`config.ts` 中没有开 `ignoreDeadLinks`，意味着 `npm run docs:build` 会因为坏链接直接报错。修文档时如果改了文件名或路径，记得 grep 一下旧链接。
:::

### 3.5 GitHub 风格扩展

- 表情：`:tada:` → 🎉
- 目录：在文档任意位置写 `[[toc]]` 会渲染当前页大纲
- 代码导入：`<<< @/path/to/file.ts` 可直接引用仓库文件内容

## 四、本地预览效果

开发服务器跑在 **5174 端口**（前端 SPA 跑在 5173，互不冲突）。

### 4.1 只启动文档

```bash
npm run docs:dev
```

打开 `http://localhost:5174/docs/`。保存任意 `.md` 文件，浏览器会自动热更新，无需手动刷新。

### 4.2 同时启动 SPA + 文档

```bash
npm run dev
```

这条命令会通过 `run-p` 并行起两个服务：

- 前端 SPA：`http://localhost:5173/`
- 文档：`http://localhost:5174/docs/`

需要在文档里贴一个 SPA 跳转链接，或者改完文档想顺手验证应用还能跑，用这条更方便。

### 4.3 预览生产构建

热更新的开发模式跟生产构建在路由、压缩、`base` 路径上有细微差别。发 PR 前建议跑一次：

```bash
npm run docs:build      # 输出到项目根 dist-docs/
npm run docs:preview    # 以静态文件方式起服务，仍是 5174 端口
```

如果 `docs:build` 报错，常见原因：

1. **死链**：某个 `[xxx](./yyy)` 指向了不存在的文件。
2. **frontmatter 语法错**：YAML 缩进或冒号空格。
3. **TS/Vue 主题文件报错**：执行 `npm run docs:type-check` 单独检查 `.vitepress/` 下的类型。

## 五、部署相关

- **构建产物**：`dist-docs/`（在项目根，不在 `docs/` 里）。
- **路径前缀**：`base: '/docs/'` 必须与 `docker/nginx.conf.template` 中的 `location /docs/` 对齐，改了一边要改另一边。
- **镜像构建**：`docker/Dockerfile` 会把 `dist-docs/` 拷贝到 nginx 容器的对应路径。本地写文档时不需要关心 Docker，CI 会处理。

- [ ] `npm run docs:build` 通过（无死链、无 frontmatter 报错）
- [ ] 截图 / 图片 请通过图床上传，不要放在外链或 `public/` 下，不要直接塞进 `docs/`（会被打进静态产物，体积膨胀）

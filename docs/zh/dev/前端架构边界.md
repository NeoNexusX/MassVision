# 前端架构边界


## 目录职责

- `src/app`：应用级外壳，例如全局导航、全局入口组件。
- `src/views`：路由页面，只负责组装 feature 能力，不承载复杂业务逻辑。
- `src/shared`：跨业务复用的基础能力。这里可以放基础 UI、通用 composable、HTTP client、格式化工具和全局类型声明。
- `src/features/<module>`：业务模块。模块内按 `api`、`components`、`composables`、`services`、`utils`、`types`、`constants` 继续拆分。
- `src/router`：路由声明和路由守卫。
- `src/workers`：Web Worker 入口。

## 依赖方向

- `shared` 不依赖任何 `features`。
- `features` 可以依赖 `shared`，但不要随意跨 feature 引用内部文件。
- 页面组件可以引用多个 feature，用来完成业务编排。
- feature 内组件优先引用本模块的 `composables`、`services` 和 `api`，避免把请求、格式化和副作用堆进模板组件。

## 状态边界

- 组件内部交互状态放在组件本地，例如弹窗开关、输入框临时值。
- 页面或模块内复用状态放到 feature composable。
- 认证等真正全局状态放到 feature store，例如 `features/auth/stores/authStore.ts`。
- 服务端数据由 `api` 和业务 composable 管理，不直接塞进全局 store。

## 自动化约束

- `npm run type-check`：TypeScript / Vue 类型检查。
- `npm run lint:check`：检查代码和目录导入边界。
- `npm run format:check`：检查 Prettier 格式。
- `npm run check`：并行执行类型检查、lint 和单元测试。

ESLint 已限制从旧根目录别名导入，例如 `@/utils/*`、`@/components/*`。
新增通用代码放 `shared`，新增业务代码放对应 `features` 模块。

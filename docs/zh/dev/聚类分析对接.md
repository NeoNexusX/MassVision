# 聚类分析对接

> 按 2026-08-24 的前端实现整理。本文描述当前 UI 和读取器实际依赖的契约，不承诺未在代码中使用的后端行为。

## 功能边界

- UMAP 只在 `continuous` 结果上提供，由后端异步生成。
- KMeans 不调用后端聚类接口，而是在浏览器中用 `ml-kmeans` 处理 UMAP embedding。
- UMAP 和主算法结果共用同一个 run Zarr；不存在单独的 clustering Zarr。

## 前端流程

```text
进入 Continuous 结果页
  └─ 静默尝试读取 analysis/umap
       ├─ 已存在：加载并启用 UMAP/KMeans
       └─ 不存在或读取失败：保持未启用，等待用户确认

用户确认 Generate UMAP
  └─ POST /processes/{run_id}/clustering（无请求体）
       ├─ completed：读取 Zarr，读取成功后才标记 ready
       ├─ failed / error_message：停止轮询并显示错误
       └─ 其他状态：每 5 秒再次 POST 检查状态
```

轮询只维护一个 timer，run 切换或组件卸载时会停止。临时请求错误不会立刻结束轮询；`completed` 和失败状态都会结束轮询。当前错误区的 `Retry` 只重读 Zarr 数据，不应描述成“重新创建后端任务”。

## 聚类任务接口

```http
POST /processes/{run_id}/clustering
Authorization: Bearer <token>
```

- 路径参数：`run_id`
- 请求体：无
- 前端至少要求响应包含数值型 `id`，否则视为无效响应。
- 当前使用的响应字段：

| 字段 | 用途 |
|---|---|
| `id` | 校验任务响应 |
| `clustering_status` | 判断完成、失败或继续轮询 |
| `error_message` | 非空时按失败处理并展示 |
| `status`、`finished_at` 等 | 类型中保留，但不控制当前聚类 UI |

前端将该 POST 作为 create-or-fetch/status check 使用。不要在文档中进一步承诺所有状态下的后端幂等语义；尤其失败状态下，当前 UI 会停止自动 POST。

## 获取 Zarr 访问参数

```http
GET /processes/{run_id}/zarr
Authorization: Bearer <token>
```

当前响应结构：

```json
{
  "folder_path": "processed/run_45.zarr/",
  "bucket": "bucket-name",
  "region": "cn-hangzhou",
  "sts_token": {
    "AccessKeyId": "...",
    "AccessKeySecret": "...",
    "SecurityToken": "...",
    "Expiration": "2026-08-24T12:00:00Z"
  },
  "expires_in": 3600
}
```

不要添加旧参数 `zarr_type=clustering`。算法数据和 `analysis/umap` 都从 `folder_path` 指向的同一目录读取。OSS client 会在到期前刷新 STS；遇到 token expired/403 时还会刷新并重试一次。

## Zarr v3 数据契约

```text
<root>/zarr.json
<root>/analysis/umap/zarr.json
<root>/analysis/umap/coordinates/zarr.json
<root>/analysis/umap/scaled_embedding/zarr.json
```

| 数据 | 类型与形状 | 约定 |
|---|---|---|
| 根属性 `spatial_shape` | `[height, width]` | 栅格尺寸，不能用坐标最大值推导 |
| `coordinates` | `uint32[n, 2]` | `(x, y)`，已是 0-based；不要减根 `coordinate_base` |
| `scaled_embedding` | `float32[n, 3]` | 三维 UMAP 值，预期在 `[0, 1]` |

group 的准确路径是 `analysis/umap`，不是旧文档中的 `anay`。

`ClusteringZarrStore` 会校验 Zarr v3 group、数组 dtype/shape 和两数组的行数。栅格化规则是：

```text
R = round(scaled_embedding[i, 0] * 255)
G = round(scaled_embedding[i, 1] * 255)
B = round(scaled_embedding[i, 2] * 255)
pixel = coordinates[i] = (x, y)
```

没有数据的格点保持 `(0, 0, 0)`，转为页面 RGBA overlay 或导出 PNG 时作为透明背景。UMAP overlay 尺寸必须与离子图一致，否则显示错误。

## 本地 KMeans

- 输入是原始 `coordinates` 和 `scaled_embedding`，不是栅格 PNG。
- 用户可设置 `k = 2–20`，默认输入为 5。
- 计算在 `kmeans.worker.ts` 中完成；当前固定 seed 42、最大迭代 30。
- 输出标签映射回 `spatial_shape` 网格，背景标签为 `-1`。
- 重新运行会替换当前结果；cluster 选择同时控制 overlay 和导出 mask。
- 后端 Zarr 不需要也不会被当前前端读取任何 KMeans labels/颜色数组。

## 关键实现文件

| 文件 | 职责 |
|---|---|
| `src/services/clustering/api/clusteringApi.ts` | POST 聚类任务 |
| `src/services/clustering/clusteringZarrStore.ts` | 读取 UMAP 数组并栅格化 |
| `src/services/zarr/api/zarrAccessApi.ts` | 获取同一 run 的 Zarr/STS 参数 |
| `src/features/workspace/results/composables/useOverlayData.ts` | 探测、轮询、overlay、导出和缓存生命周期 |
| `src/features/workspace/results/utils/kmeans.ts` | KMeans 调度与校验 |
| `src/features/workspace/results/utils/kmeans.worker.ts` | Worker 内本地聚类 |

修改接口、group 路径、dtype/shape、坐标基准或状态值时，必须同步修改类型、读取器、结果页状态机和本页中英文文档。

# 图标使用规范

项目里的图标已经从混杂的「裸写 `<svg>` / 直接 import `@heroicons/vue` 组件 / `@iconify/vue`」三套并存，统一收敛成 **只用 Iconify**。本页讲清楚日常怎么用、新增图标要改哪几个文件，以及为什么要多这一步。

## 一、两种用法

### 1.1 业务语义图标：`<SvgIcon type="..." />`

绝大多数场景用这个。[SvgIcon.vue](https://github.com/NeoNexusX/MassVision/blob/main/src/shared/components/SvgIcon.vue) 是全局注册的薄封装组件，`type` 对应 [svgIcons.ts](https://github.com/NeoNexusX/MassVision/blob/main/src/shared/components/svgIcons.ts) 里 `ICON_MAP` 的语义名（如 `warning`、`plus`、`close`），编译期会校验拼写：

```vue
<SvgIcon type="warning" class="h-5 w-5 text-error" />
```

好处是业务代码里不出现具体图标库的命名细节，换图标只改 `svgIcons.ts` 一处。

### 1.2 一次性图标：`<Icon icon="prefix:name" />`

不打算复用、只在某一个组件里出现一次的图标（比如品牌 logo），直接用 `@iconify/vue` 的 `Icon` 组件，不必为它专门进 `ICON_MAP`：

```vue
<script setup lang="ts">
import { Icon } from '@iconify/vue'
</script>

<template>
  <Icon icon="simple-icons:github" class="h-5 w-5" />
</template>
```

### 1.3 图标集怎么选

- 通用 UI 图标：优先 `heroicons:*`（项目主力图标集，已离线打包）。
- 品牌 / 第三方服务 logo（GitHub、微信、阿里云……）：用 `simple-icons:*`。
- **不要随手引入新的图标集**（比如 `mdi:*`）。一个新图标集即便只用一个图标，也要整包下载、整包过一遍离线打包流程，得不偿失。先去 [icon-sets.iconify.design](https://icon-sets.iconify.design/) 搜一下 `heroicons` 里有没有语义相近的，几乎总能找到。

## 二、为什么要「离线打包」

`@iconify/vue` 的 `<Icon icon="prefix:name"/>` 默认行为是：本地缓存没有这个图标时，运行时向 Iconify 的公共 API（`api.iconify.design`）发请求拉取。这意味着应用会偷偷依赖一个外部网络服务——本地开发机联网，所以不会发现问题，但部署到无法访问公网的环境时，没缓存住的图标会直接显示空白。

为了不依赖这个外部服务，项目在构建前用脚本把实际用到的图标子集从官方数据包里抽出来，生成一个几十 KB 的小文件，应用启动时把这个小文件注册进 Iconify 的本地缓存（`addCollection()`），运行时完全不联网。

相关文件：

```
scripts/
├── iconNames.mjs           # 图标名清单——离线打包的唯一真相来源
└── build-icon-bundle.mjs   # 读取清单，从 @iconify-json/* 抽取子集，写出 bundle

src/shared/icons/
├── offlineRegistry.ts            # 启动时 addCollection() 注册，main.ts 里 import
└── iconBundle.generated.json     # 生成文件，已提交进 git，不要手改
```

::: tip 为什么不直接 `import` 官方图标包再过滤
试过这个做法，结论是不行：`getIcons()` 过滤只在**运行时**生效，构建工具仍会把整个原始 JSON（heroicons ~630KB，simple-icons ~4.7MB）打进产物——完全没达到精简的目的。所以改成在**构建前**用 Node 脚本生成好精简版，运行时只 import 这个精简版。
:::

## 三、新增图标的步骤

只有当你要用一个**当前清单里没有**的图标时才需要走这个流程；用已经在 `ICON_MAP` 里的图标完全不受影响。

1. **确认图标名**：去 [icon-sets.iconify.design](https://icon-sets.iconify.design/) 搜，记下 `集合:图标名`（如 `heroicons:beaker`）。
2. **加进清单**：编辑 [scripts/iconNames.mjs](https://github.com/NeoNexusX/MassVision/blob/main/scripts/iconNames.mjs)，把图标名加进对应集合的数组里。
3. **重新生成 bundle**：
   ```bash
   npm run icons:bundle
   ```
   几秒钟内会重写 `src/shared/icons/iconBundle.generated.json`。
4. **在代码里用**：业务语义图标加进 `svgIcons.ts` 的 `ICON_MAP` 再用 `<SvgIcon type="..."/>`；一次性图标直接 `<Icon icon="..."/>`。
5. **一并提交**：把第 2、3 步改动的 `scripts/iconNames.mjs` 和 `iconBundle.generated.json` 跟业务代码放在同一个 commit / PR 里。

::: danger 忘记第 2-3 步不会在本地暴露问题
本地开发机联网，漏加的图标会自动回退去请求 Iconify 公共 API，看起来"还是显示出来了"。但部署到无公网访问的环境后，这个图标就会空白。**改完图标后留意一下 `git status` 里有没有 `iconBundle.generated.json` 的改动**，是检查自己有没有漏步骤最简单的办法——改了图标名但这个文件没变，基本就是忘了跑 `icons:bundle`。
:::

## 四、验证离线生效

想确认某个图标确实走的是本地缓存而不是联网请求，开发时打开浏览器 DevTools → Network 面板，过滤 `iconify`，刷新页面：

- 没有任何请求打到 `api.iconify.design`：离线生效。
- 出现了请求：说明用到的图标没有被收进 `iconBundle.generated.json`，回去检查 `scripts/iconNames.mjs` 和图标名是否拼写一致（连字符 `-` 容易漏)。

## 五、提交前自检清单

- [ ] 新图标已经在 [icon-sets.iconify.design](https://icon-sets.iconify.design/) 确认存在，优先用 `heroicons:*`
- [ ] `scripts/iconNames.mjs` 已加上新图标名
- [ ] 跑过 `npm run icons:bundle`，且 `iconBundle.generated.json` 的改动跟着一起提交
- [ ] `npm run type-check` / `npm run build` 通过
- [ ] Network 面板确认没有对 `api.iconify.design` 的请求

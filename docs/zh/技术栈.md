# 技术栈.md 完善版
## 一、环境搭建
### 1.1 基础环境依赖
- 操作系统：Windows/macOS/Linux（推荐 macOS/Linux 开发）
- Node.js：建议 `^20.0.0`（匹配 Vite 7.x 最佳实践，可通过 `nvm` 管理多版本）
- npm：`^9.0.0` 或 yarn/pnpm（项目默认使用 npm）

### 1.2 项目初始化命令
```bash
cd MassFlow
npm install
npm run format

# 启动开发服务器（默认端口：5173，可在 vite.config.ts 中修改）
npm run dev
```

## 二、项目结构
```
MassVision/
├── .env.example          # 环境变量示例（需复制为 .env 并配置实际值）
├── .eslintrc.cjs         # ESLint 配置（Vue/TS 规则、prettier 集成）
├── .prettierrc.json      # Prettier 格式化规则（与 ESLint 无冲突）
├── package.json          # 依赖声明、脚本命令核心配置
├── playwright.config.ts  # Playwright E2E 测试配置
├── tsconfig.json         # TypeScript 全局配置（compilerOptions + 路径别名）
├── vite.config.ts        # Vite 构建核心配置（插件、环境变量、构建优化）
├── vitest.config.ts      # Vitest 单元测试配置（与 Vite 共享配置）
├── public/               # 纯静态资源（不经过 Vite 构建，直接复制到 dist）
│   ├── favicon.ico       # 站点图标
│   └── robots.txt        # 搜索引擎爬虫规则
└── src/                  # 业务源码核心目录
    ├── main.ts           # 应用入口：创建 Vue 实例、注册 Pinia/router 插件
    ├── router/           # 路由模块
    │   └── index.ts      # 路由定义、守卫、路径映射（createWebHistory 模式）
    ├── stores/           # Pinia 状态管理
    │   └── counter.ts    # 示例 Store：组合式 API 实现状态管理
    ├── components/       # 通用UI组件（全局注册/局部引入）
    ├── views/            # 页面级组件（与路由一一对应）
    │   └── Login.vue     # 登录页（路由默认重定向目标）
    ├── assets/           # 编译型资源（样式、图片、字体等）
    └── utils/            # 工具函数库（核心通用能力）
        ├── http.js       # Axios 封装（实例化、拦截器、错误处理）
        └── auth.js       # 认证工具（密码加密、token 解析/校验）
```

### 2.1 核心目录/文件详解
| 路径                | 核心作用 & 实现细节                                                                 |
|---------------------|-------------------------------------------------------------------------------------|
| `src/main.ts`       | 采用 Vue 3 组合式 API 风格，通过 `createApp` 创建实例，链式调用 `use(pinia)` + `use(router)` 注册插件，最后挂载到 `#app` 节点 |
| `src/router/index.ts` | 基于 `createWebHistory` 实现 HTML5 History 模式路由，根路径 `'/'` 重定向至 `/login`；内置 jwtToken 路由守卫模板（注释态），可快速适配权限控制 |
| `src/utils/http.js` | 封装 Axios 实例，读取 `import.meta.env.VITE_API_BASE` 作为接口基准地址；请求/响应拦截器为注释态，预留 token 注入、错误统一处理逻辑 |
| `src/utils/auth.js` | 基于 `crypto-js/sha256` 实现密码不可逆加密，返回 Hex 格式密文；无 token 生成/解析逻辑，需结合后端 jwt 规则扩展 |
| `src/stores`        | 采用 Pinia 组合式 `defineStore` 定义状态，无嵌套模块（Pinia 原生支持扁平化管理），示例 counter store 包含 `count` 状态 + `increment` 行为 |

## 四、核心实现细节（基于源码）
### 4.1 应用入口（src/main.ts）
- 采用 Vue 3 组合式 API 风格，无 Options API 混用，符合现代 Vue 开发规范
- 先注册 Pinia 再注册 Router，保证路由守卫中可正常访问 Pinia Store
- 未开启 `app.config.errorHandler` 全局错误捕获（可扩展：添加前端错误监控）

### 4.2 路由系统（src/router/index.ts）
- 路由模式：`createWebHistory`（需后端配置 fallback，避免刷新 404）
- 路由守卫：注释态的 `router.beforeEach` 守卫，逻辑为校验 localStorage 中的 `jwtToken`，无 token 则跳转 `/login`
- 路由懒加载：未显式配置（可优化：通过 `import('@/views/Login.vue')` 实现按需加载，减少首屏体积）
- 默认路由：`{ path: '/', redirect: '/login' }`，保证应用启动直接进入登录流程

### 4.3 网络请求封装（src/utils/http.js）
- Axios 实例化：`baseURL` 读取 `import.meta.env.VITE_API_BASE`（环境变量需以 `VITE_` 前缀，Vite 才会暴露）
- 拦截器设计：
  - 请求拦截器：注释态逻辑为添加 `Authorization: Bearer ${token}` 请求头
  - 响应拦截器：注释态逻辑为统一处理 401（token 过期）、500（服务端错误）等状态码
- 错误处理：无全局错误捕获（可扩展：结合 Element Plus/Naive UI 实现错误提示）

### 4.4 认证工具（src/utils/auth.js）
- 加密算法：`CryptoJS.SHA256`（不可逆加密，适合密码传输前处理）
- 实现细节：将密码字符串转换为 Hex 格式密文，无加盐逻辑（可优化：添加随机盐值，提升安全性）
- 依赖说明：`crypto-js` 未在 package.json 中声明，需手动安装（非核心依赖，避免无加密需求时冗余）

### 4.5 状态管理（src/stores/counter.ts）
- Store 定义：`defineStore('counter', () => { ... })` 组合式风格
- 状态设计：`count` 响应式状态 + `increment` 同步方法，无异步 action 示例（可扩展：添加 `fetchUserInfo` 等异步逻辑）
- 持久化：未使用 `pinia-plugin-persistedstate`（可扩展：实现 Store 状态 localStorage 持久化）

## 六、开发规范与最佳实践
### 6.1 代码规范
- 命名规则：
  - 组件名：PascalCase（如 `Login.vue`），符合 Vue 官方规范
  - 变量/函数名：camelCase（如 `getUserInfo`），避免下划线/连字符
  - 常量：UPPER_CASE（如 `const API_BASE = import.meta.env.VITE_API_BASE`）
- 注释规范：
  - 组件/函数：JSDoc 注释（如 `/** 登录接口请求 @param {string} username - 用户名 @returns {Promise<User>} */`）
  - 复杂逻辑：单行注释 `//` 说明核心思路，避免无意义注释

### 6.2 开发流程建议
1. 分支管理：基于 `main` 分支创建功能分支（如 `feature/login-optimize`），避免直接修改主分支
2. 提交规范：提交信息遵循 `type: description`（如 `feat: 完善登录页密码加密`、`fix: 修复路由守卫token校验逻辑`）
3. 提测前检查：
   - 执行 `npm run format` + `npm run lint` 保证代码规范
   - 执行 `npm run type-check` 保证类型无错误
   - 执行 `npm run test:unit` 保证单元测试通过率 100%
4. 环境变量配置：
   - 开发环境：`.env.development` 配置 `VITE_API_BASE = 'http://localhost:3000/api'`
   - 生产环境：`.env.production` 配置真实后端接口地址，CI/CD 部署时注入

### 6.3 性能优化方向
1. 构建优化：在 `vite.config.ts` 中开启 `build.rollupOptions`，配置 `external` 减少打包体积（如将 `axios` 改为 CDN 引入）
2. 路由优化：开启路由懒加载，结合 `Suspense` 实现加载中状态
3. 样式优化：开启 TailwindCSS 摇树优化（`purge` 配置），移除未使用的样式类
4. 依赖优化：使用 `npm dedupe` 去重依赖，减少 `node_modules` 体积

### 6.4 扩展开发建议
1. 依赖扩展：
   - 如需 UI 组件库：推荐 Naive UI（轻量、TypeScript 友好），避免引入 Element Plus 导致体积过大
   - 如需状态持久化：安装 `pinia-plugin-persistedstate`，实现 Store 自动持久化
2. 功能扩展：
   - 登录流程：完善 `src/utils/http.js` 拦截器，实现 token 过期自动刷新
   - 错误监控：集成 Sentry，捕获前端运行时错误
   - 接口文档：集成 Swagger/OpenAPI，自动生成接口类型定义

## 七、常见问题与解决方案
| 问题现象                          | 根因分析                                  | 解决方案                                                                 |
|-----------------------------------|-------------------------------------------|--------------------------------------------------------------------------|
| 启动 `npm run dev` 提示端口被占用 | 5173 端口被其他进程占用                   | 修改 `vite.config.ts` 中 `server.port` 为 5174/8080 等，或杀掉占用进程    |
| 构建时报 `TS2322` 类型错误        | TypeScript 类型推断失败/类型不匹配        | 执行 `npm run type-check` 定位具体文件/行号，补充类型注解或修正类型定义   |
| 路由刷新后 404                    | 后端未配置 History 模式 fallback          | Nginx 配置 `try_files $uri $uri/ /index.html;`，Apache 配置 `FallbackResource /index.html` |
| `crypto-js` 找不到模块            | 未安装该依赖                              | 执行 `npm install crypto-js --save`，并在 `tsconfig.json` 中添加类型声明  |
| E2E 测试失败                      | 预览服务器未启动/测试用例定位元素失败     | 先执行 `npm run build && npm run preview`，再运行 `npm run test:e2e`；检查元素选择器是否正确 |

## 八、CI/CD 与生产部署建议
### 8.1 构建产物说明
- 构建输出目录：`dist/`（可在 `vite.config.ts` 中修改 `build.outDir`）
- 产物结构：静态 HTML/CSS/JS + 静态资源，无服务端代码，可部署至任意静态服务器

### 8.2 部署方式
1. 静态服务器：Nginx/Apache/Caddy（推荐 Nginx，配置 gzip 压缩提升加载速度）
2. 云平台：Vercel/Netlify/GitHub Pages（无需配置后端，自动构建部署）
3. 容器化：Docker + Nginx（Dockerfile 示例）：
   ```dockerfile
   FROM node:20-alpine AS build
   WORKDIR /app
   COPY . .
   RUN npm install && npm run build

   FROM nginx:alpine
   COPY --from=build /app/dist /usr/share/nginx/html
   COPY nginx.conf /etc/nginx/conf.d/default.conf
   EXPOSE 80
   CMD ["nginx", "-g", "daemon off;"]
   ```

### 8.3 生产环境注意事项
- 环境变量：通过 CI/CD 注入 `VITE_API_BASE`，避免硬编码后端地址
- 静态资源：开启 CDN 加速（如阿里云 OSS/七牛云），修改 `vite.config.ts` 中 `base` 为 CDN 地址
- 性能监控：集成 Google Analytics/百度统计，监控页面加载速度、用户行为
- 安全配置：Nginx 开启 HTTPS、配置 CSP 策略，避免 XSS/CSRF 攻击

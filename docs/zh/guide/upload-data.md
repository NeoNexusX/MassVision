# 上传数据

本页说明当前 imzML 上传流程。上传入口位于登录后的 **My Datasets → Upload New Dataset**。

## 文件要求

- 必须同时选择一个 `.imzML` 和一个 `.ibd` 文件。
- 两个文件的主文件名必须完全一致，扩展名大小写不影响识别。
- 前端会检查 imzML 是否包含基本结构标签；解析失败时不会阻止你重新选择文件。
- 公开数据集的 `.ibd` 文件不得小于 **10 MB**；私有数据集没有这项前端限制。

## 填写元数据

选中文件后，前端会尝试从 imzML 自动读取极性、离子源、分析仪、像素尺寸、Spectrum Mode 和 Storage Mode。没有识别出的内容需要手动填写；手动修改已识别的 Spectrum/Storage Mode 时会出现二次确认。

以下字段始终必填：

| 分组 | 字段 |
|---|---|
| 采集信息 | Polarity、Ionisation Source、Analyzer、Pixel Size X/Y、Spectrum Mode、Storage Mode |
| 样本信息 | Organism、Organism Part、Condition、Sample Stabilization |

补充规则：

- Pixel Size X/Y 必须是 `1–200` 的整数。
- Sample Growth Conditions 和 Tissue Modification 可选。
- Detector resolving power 下的 m/z 与 Resolving Power 可选，合法数值会以数字提交。
- Solvent、MALDI Matrix 和 MALDI Matrix Application 是否必填由离子源规则决定（定义在 `src/features/upload/utils/ionSourceRules.ts`）。表单默认带有 `100% Water`；MALDI 类离子源通常还要求基质及施加方式。
- 选择下拉框中的 **Other** 后必须填写自定义值，不能直接提交 `Other`。

## 公开与私有

**Make dataset public (visible to others)** 当前默认勾选：

- 保持勾选：上传前需要再次确认，完成后其他用户可见；`.ibd` 至少 10 MB。
- 取消勾选：数据集只在自己的 **My Datasets** 中可见。

现有私有数据集也可以在详情页通过 **Make Public** 公开；该操作在当前 UI 中不可逆。

## 实际上传流程

点击 **Confirm & Upload** 后，前端按以下顺序执行：

1. 在 Web Worker 中分块计算两个原始文件的组合 MD5。
2. 调用预检接口，用原始大小和 MD5 检查服务端是否已有相同数据。
3. 若服务端可复用，直接完成，不再压缩或上传。
4. 若不能复用，先取得 OSS STS 临时凭证并开启一次 multipart upload —— 必须在压缩之前，因为压缩即上传。
5. Worker 流式生成 ZIP64 归档，产物切成分片交给主线程用 `ali-oss` 直传 OSS。**归档不落本地磁盘**：Worker 产出多少就传多少，中间只保留几个分片的缓冲。
6. 全部分片上传完成后合并分片，并清除本地续传会话。

归档内容：`.imzML` 与 `.ibd` 都用浏览器原生压缩流压缩。`.ibd` 是浮点二进制，压缩率只有 0.85~0.95，换来的传输量减少有限，但实测压缩仍远快于上传，这笔 CPU 是划算的。

分片大小按数据集总大小（两个源文件之和）分三档：5GB 以下用 10MB，5~10GB 用 50MB，10GB 以上用 128MB。上传并发默认 2，网速足够快时会自动提高（上限随片长收窄，分别是 4 / 4 / 2），以控制浏览器端的峰值内存。

进度面板会显示当前阶段、百分比、速度和预计剩余时间。百分比的口径是**已确认落到 OSS 的源文件字节 / 源文件总大小**，所以它衡量的是「数据安全了多少」；面板还会把速度拆成压缩与上传两项，并标出哪一端是瓶颈。`.imzML` 全部传完时会单独提示一次，并给出这一段的平均压缩与上传速度。

**Abort Upload** 会作废 OSS 上已传的分片并保留 `file_id` 与凭证，下次可以重新发起。已经发出的那个分片请求浏览器无法取消，可能还会在后台传一两分钟。

## 断点续传

续传信息保存在当前站点的 `localStorage`。归档不再缓存到本地，因此：

- **续传必须重新选择同一对 `.imzML` / `.ibd` 文件，并重新压缩一遍。** 已经传到 OSS 的分片不会重传，但为了让分片边界对得上，压缩流要从头跑到断点位置。
- 依据是「同样的输入 → 同样的 ZIP 字节」。前端会在重新生成第一个已完成分片时用它的 MD5 与保存的 ETag 比对；对不上就作废整轮、要求重新上传，绝不会把两次压缩的字节拼到同一个对象上。
- 必须使用同一浏览器和同一站点来源；清理站点数据会丢失续传会话。
- STS 会话过期后不能继续使用，前端会清理旧会话并要求重新上传。
- 压缩参数（是否压缩 `.ibd` 等）被调整过之后，旧会话会被直接丢弃 —— 否则要白压一遍才会发现字节对不上。
- **Resume** 复用已保存的 multipart upload 与已完成分片；主动取消后的会话会开启一轮新的 multipart upload。
- **Discard** 删除续传会话。

单个分片上传失败会自动重试一次（共两次尝试），单片超时固定 30 分钟 —— 定得足够松，正常网络下不会触发，它只兜底「连接既不报错也不推进」这一种情况。第二次仍失败会中止整次上传、保留可恢复状态并显示错误。

## 常见问题

- **文件无法选择**：确认两个文件一次选中，且主文件名一致。
- **元数据无法提交**：检查所有星号字段、像素尺寸和离子源动态字段；`Other` 必须补充具体值。
- **公开上传被拒绝**：检查 `.ibd` 是否至少 10 MB。
- **没有 Resume**：凭证阶段可能尚未完成，或站点数据、STS 会话已经失效；也可能是还没重新选中同一对源文件（续传需要它们）。
